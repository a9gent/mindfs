# 完整方案 v2（需求 1-6 全覆盖：bug修复 → 列表体验 → 全局搜索 → 批量清理 → 平铺 → 看板互通 → 蓝环扩展 → 部署/PR）

## 调研结论（关键代码事实）

**需求1-4 调研结论**（上轮已确认）：
- 搜索 bug 根因：App.tsx:5309 `sessionListMode === "local"` 门控——多项目模式下搜索根本不发请求；另有 <2 字符静默返回、错误吞成空数组两处小坑。后端 `/api/sessions/search` 本身支持 name/user/reply 全文匹配 + `multi_root=1` 全局搜索。
- `expandedProjects` 是纯内存 state（SessionList.tsx:854），不持久化，无全折叠按钮。
- 删除无多选；`deleteSession` + handleDeleteSession 级联子会话逻辑可复用。
- 平铺所需数据齐全：`multiProjectSessionGroups` 每组带 rootName，`projectBadge` 已有先例。

**需求5 看板调研结论**：
- 列 = 任务模板的 stages（不是固定三列）；默认 3 个模板（bugfix/优化改进/新功能）在 `task_template.json` 全局种子，task 按 root_id 过滤——"自适应项目模板"天然成立（模板全局、看板按项目）。
- 看板→会话已通：看板创建任务后经 `EnsureAgentSession` 建会话，写入 `sessions.task_id`，并广播出现在会话列表（appcontext.go:297-311），会话名 = `"{模板名} / #{任务号}"`。
- **会话→看板完全缺失**：`PATCH /api/tasks/{id}` 的 `TaskPatch`（orchestration.go:115）没有 `main_session_key` 字段；`sessions.task_id` 建后不可改。schema 支持但无 API。
- StageRun 有 `session_key` 字段；`SessionReusePolicy=task_main` 意味着调度时 `EnsureAgentSession` 优先复用 `task.MainSessionKey`。

**需求6 调研结论**：
- 节点页是独立 URL `/nodes`（main.tsx:612），`ownNodePageURL()`（nodePage.ts:15）可直接跳转。
- 蓝环手势设置面板在 FileTree 汉堡菜单里（FileTree.tsx:4303→popover 4622），是 popover 无路由，需把 `openBlueRingSettings`（FileTree.tsx:2708）通过 ref/prop 暴露出去。
- 看板操作 API 齐全：createTask / moveTask(next|run-now|pause|resume|complete|cancel) / patchTask / openTaskCreateDialog / openTaskEditDialog / handleMoveKanbanTask 全部现成。
- 蓝环扩展模式：quickSwitch.ts 三件套 + SessionQuickActions runAction + ActionBar 透传 + App.tsx handler。

## A. 修 bug：侧栏搜索（最优先）
1. 去掉 `sessionListMode === "local"` 门控，多项目模式照常搜索（multiRoot 跟随开关）。
2. 最短长度 1 字符；加 300ms debounce。
3. 失败/空结果给可见反馈（toast + "无匹配"空态），不再静默。

## B. 会话列表折叠增强（需求1）
1. `expandedProjects` 持久化到 localStorage `mindfs-session-projects-expanded`（存"已折叠集合"，默认展开）。
2. 多项目列表头部加一键「全部折叠 ⇄ 全部展开」循环按钮。

## C. 蓝环「全局搜索」+ 搜索卡片（需求2）
1. quickSwitch.ts 加 `globalSearch` action；i18n 两个 locale。
2. 新建 `GlobalSearchDialog.tsx`（portal 遮罩卡片）：输入即搜（debounce 300ms）走 `searchSessions("", q, 50, {multiRoot:true})`；结果带来源标签（标题/用户/回复）+ snippet 高亮 + 项目名 + 相对时间；↑↓/Enter/Esc 键盘导航；打开命中会话（handleSelectSession 带 root_id）。
3. **筛选做减法**：不做手动项目多选。只保留一个 scope 切换：全局 ⇄ 当前项目（覆盖绝大多数场景）。

## D. 闲置会话批量清理（需求3）
1. 多项目列表头部「清理闲置」按钮 → 多选模式：卡片出现勾选框；顶部工具条 = 时效（3天/5天/7天，按 updated_at）+ 正序/倒序（默认倒序=最旧在前）+ 全选可见。
2. 底部浮条「已选 N · 删除」→ 确认弹窗（列出数量）→ 逐个 deleteSession（级联子会话），带进度与失败计数，完成 toast 退出。
3. 当前打开/运行中会话禁用勾选；Esc 退出。

## E. 平铺模式（需求3追加）
1. 设置项「平铺会话列表」localStorage `mindfs-flat-session-list`，仅多项目开启时可见。
2. 平铺开启时：已置顶专区下方单一列表，全部组 flatten 按 updated_at 排（尊重 sortAsc），每卡带 projectBadge；分页沿用逐组 remaining 逻辑；组折叠 UI 在平铺下隐藏。

## F. 会话 ↔ 看板双向互通（需求5）
**后端最小改动（2处）**：
1. `TaskPatch` 加 `MainSessionKey *string`，`PatchTask` 校验会话存在且同 root 后写入（只在为空时可设，防止抢绑）；复用现有 `upsertTask` 持久化。
2. `session.Manager` 加 `SetTaskID(key, taskID)`（对齐 Rename 模式：加锁→校验→写 meta→broadcast 由 handler 做）。
3. 新路由 `POST /api/tasks/{id}/attach-session` `{root_id, session_key}`：写 `task.MainSessionKey` + `sessions.task_id` 双向绑定，广播 SessionMetaUpdated + TaskUpdated；并补一条 `attached` 事件。防重：session 已 task_id 时 409。

**前端**：
1. 会话卡 3 点菜单加「添加到任务看板」（SessionList.tsx onHandoffPack 旁，新模式照抄）。
2. 新建 `AddToKanbanDialog.tsx`：列出该项目看板用到的全部模板（`fetchTaskTemplates` + 去重聚合，模板增删改自动适应）；点模板创建任务（`createTask` 带 `input` = 会话名），创建后立即调 attach-session 把当前会话绑为该任务的 main_session。
3. **命名策略（最优解）**：不整体改会话名。在会话名**前方**追加模板标准化前缀 `{模板名} / `（对齐看板原生命名格式），保留用户原语义；仅当会话名与模板名重复时才只留前缀。实现用现有 session rename API。
4. 默认插入阶段一（backlog/待开始）而非阶段二——看板任务必须从 stage 0（user 角色）起步，这是 `createTask` 的硬约束（service.go:207 要求首阶段 Role==User）；阶段推进交给现有 next/run-now 流程，用户在卡片里可立即「启动任务」。
5. 不影响原有看板逻辑：attach 只在空任务上写 main_session_key；调度时 `task_main` 复用策略天然把该会话当主会话，无新分支。

## G. 蓝环新动作（需求6）
加 5 个 action（默认 none，避免打架；与现有动作无功能重叠）：
1. `openNodesPage` → `window.location.assign(ownNodePageURL())`，弹出前如有未保存草稿给 toast 提示。
2. `openGestureSettings` → FileTree 暴露 `openBlueRingSettings`（新增 prop 传递 ref/回调），直达手势面板。
3. `kanbanCreateTask` → 切看板视图 + 打开创建任务对话框（现有 openTaskCreateDialog）。
4. `kanbanEditTask` → 看板视图 + 打开当前选中任务编辑对话框（无选中则 toast 提示先选任务）。
5. `kanbanStartTask` / `kanbanCompleteTask`（合并说明：对选中任务分别调 run-now / complete，无选中 toast；完成需 waiting_user 状态，失败给 toast）。
「创建任务/编辑任务」与看板视图内按钮同源不冲突；快捷键只做导航+触发，具体操作仍在对话框/看板内确认。
